# GOVERNMENT POLYTECHNIC COLLEGE MASAB TANK – COMPLETE PROJECT CONTEXT

## 1. Project Title

**Government Polytechnic College Masab Tank – College Website**

This is a final-year Diploma CSE project for **Government Polytechnic College, Masab Tank, Hyderabad, Telangana**.

The project is a modern, responsive college website with a Student Portal that integrates live Telangana SBTET services.

---

# 2. Main Purpose of the Project

The purpose of the project is to create a professional digital platform for the college where students, faculty, parents and visitors can access college information and student-related academic services.

The website provides:

* College information
* Departments
* Faculty information
* Events and programs
* Gallery
* Placements
* Contact information
* Quick links
* Student Portal
* Live attendance
* Live examination results

The important feature of the project is that student attendance and results are intended to be fetched from **official SBTET services**, instead of using dummy or hardcoded student data.

---

# 3. Project Architecture

The project follows this architecture:

```text
                 USER
                   |
                   v
          React Frontend
                   |
                   | HTTP Request
                   v
          Node.js + Express
                   |
                   | API Request
                   v
          Telangana SBTET API
                   |
                   | JSON Response
                   v
          Node.js Backend
                   |
                   | Processed JSON
                   v
          React Frontend
                   |
                   v
               USER
```

For example, when a student checks attendance:

```text
Student enters PIN
       ↓
React Attendance Page
       ↓
GET /api/attendance?pin=XXXX
       ↓
Express Backend
       ↓
SBTET Attendance API
       ↓
Attendance JSON
       ↓
Backend processes JSON
       ↓
React displays attendance
```

# 6. Backend

The backend uses:

**Node.js + Express.js**

The backend is important because the React frontend should not directly handle the SBTET service logic.

The backend:

1. Receives the student's request.
2. Validates the input.
3. Calls the SBTET API.
4. Receives SBTET data.
5. Parses the response.
6. Extracts required information.
7. Sends clean JSON to React.

---

# 7. Why Express.js Is Used

Express.js is a Node.js framework used to create the backend server and API routes.

For example:

```text
GET /api/attendance
GET /api/result
```

The Express server handles these requests and communicates with SBTET.

---

# 8. CORS

CORS means:

**Cross-Origin Resource Sharing**

It allows the React frontend and Node.js backend running on different origins/ports to communicate.

Example:

```text
Frontend
http://localhost:5175

Backend
http://localhost:5000
```

Because the ports are different, CORS needs to allow the frontend to communicate with the backend.

The backend configuration used during development was:

```js
app.use(
  cors({
    origin: true,
    credentials: false,
  })
);
```

# 34. Important Attendance Parsing Fix

One major issue occurred because SBTET sometimes returned JSON inside a JSON string.

The correct parsing approach was:

```js
let data = JSON.parse(rawText);

if (typeof data === "string") {
  data = JSON.parse(data);
}
```

Then:

```js
data.Table
data.Table1
data.Table2
```

can be accessed.

Without this fix, the application could show:

```text
NO STUDENT ROW FOUND
```

even though SBTET returned HTTP 200 and actual data.

# 35. Attendance Exam-Purpose Percentage

The website should display the attendance percentage used for examination purposes.

SBTET can provide:

```text
TotalPercentage
```

or:

```text
ExamsPer
```

while:

```text
Percentage
```

can represent normal attendance.

The preferred logic is:

```js
const value =
  attendance?.student?.totalPercentage ??
  attendance?.student?.percentage;
```

The project should not replace live SBTET data with manually entered attendance.

# 83. Important SBTET Rule

SBTET response structures can vary.

Therefore, the backend should inspect the actual response rather than assuming every response has exactly the same fields.

For example:

```text
Table
Table1
Table2
```

for Attendance and different structures for Results.

The parser should be flexible enough to handle the actual response structure.

# 88. Viva – What Is React?

React is a JavaScript library used to build the frontend user interface using reusable components.

---

# 89. Viva – What Is Node.js?

Node.js is a JavaScript runtime that allows JavaScript to run on the server side.

---

# 90. Viva – What Is Express.js?

Express.js is a lightweight Node.js framework used to create the backend server and API routes.

---

# 91. Viva – What Is CORS?

CORS stands for Cross-Origin Resource Sharing.

It allows a frontend running on one origin/port to communicate with a backend running on another origin/port when the server permits it.

---

# 92. Viva – What Is dotenv?

`dotenv` loads configuration values from a `.env` file into the Node.js environment.

It helps keep configuration separate from source code.

---

# 93. Viva – What Is REST API?

A REST API allows applications to communicate using HTTP requests.

For example:

```text
GET /api/attendance
GET /api/result
```

---

# 94. Viva – Why Backend Is Used?

The backend is used to:

* Communicate with SBTET
* Process API responses
* Validate requests
* Provide clean API endpoints to React
* Keep external service logic outside the frontend

---

# 95. Viva – Why Not Directly Call SBTET From React?

Using the backend provides better separation of responsibilities and allows the application to centralize:

* API communication
* Validation
* Parsing
* Error handling
* Configuration
